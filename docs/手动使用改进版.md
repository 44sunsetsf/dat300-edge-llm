# 手动使用改进版 llama.cpp（不用实验脚本，自己调参）

改进版和原版 llama.cpp **用法完全一样**，参数也一样，区别只在内部：
- 原版：只有恰好 2 台时，Pi 之间才直接交换数据；4 台和 8 台时，所有数据都要经过主控中转。
- 改进版：2、4、8、16 台时，Pi 之间都直接交换数据。

所以网上的 llama.cpp RPC 教程都适用，下面是在我们集群上的具体写法。

角色说明见 [`操作指南.md`](操作指南.md) 开头。简单说：**主控 Pi** 有模型、负责运行 llama-cli 或 llama-bench；**每台 Pi**（包括主控）都要跑一个 `ggml-rpc-server`。

---

## 第 0 步：安装程序（只做一次）

**推荐：用脚本装，【在笔记本上】，约 1 分钟。** 它只负责把程序放到每台 Pi 上，不跑任何实验。

```bash
scripts/setup_pi.sh --model      # 先按操作指南第 2、3 步填好 hosts.env、配好免密
```

**完全手动：【在每台 Pi 上】**（Pi 要能上网）

```bash
mkdir -p ~/llama.cpp && cd ~/llama.cpp
curl -L https://github.com/44sunsetsf/llama.cpp/releases/download/dat300-c1212b5/llama-c1212b5-linux-arm64.tar.gz | tar -xz
# c1212b5 是当前版本（见仓库里的 LLAMA_COMMIT）。解压后程序在 ~/llama.cpp/build/bin/。Debian 12 的 Pi 要把文件名换成 ...-linux-arm64-bookworm.tar.gz
```

装好后每台 Pi 上：
- `~/llama.cpp/build/bin/`：**改进版**
- `~/llama.cpp/build-stock/bin/`：**原版**（只有用脚本装才有）

下面的命令都用改进版。要用原版，把路径里的 `build` 换成 `build-stock`，并且**所有 Pi 都要换**。

## 第 1 步：在每台 Pi 上启动 rpc-server（包括主控）

**方法 A：【在每台 Pi 上】**，分别 ssh 上去运行：

```bash
cd ~/llama.cpp/build/bin
./ggml-rpc-server -H 0.0.0.0 -p 50052 -t 3
```

这个窗口要一直开着，Ctrl+C 停止。

**方法 B：【在笔记本上】一条命令全部在后台启动**（会读取 hosts.env）：

```bash
for h in $(source scripts/hosts.env; echo $HEAD $WORKERS); do
  ssh $h 'pkill -x ggml-rpc-server; cd ~/llama.cpp/build/bin; nohup ./ggml-rpc-server -H 0.0.0.0 -p 50052 -t 3 > /tmp/rpc.log 2>&1 &'
done
```

rpc-server 的参数：

| 参数 | 意思 | 建议 |
|---|---|---|
| `-H 0.0.0.0` | 接受其他机器的连接。**不写的话默认只接受本机，集群就连不上** | 必须写 |
| `-p 50052` | 端口。改进版还会用这个端口 +1000（51052）在 Pi 之间直接交换数据 | 保持默认 |
| `-t 3` | 计算线程数，**默认只有 2** | TP 的 decode 用 3 最快（实测比 4 快约 20%）；prefill 用 4 更快 |
| `-c` | 在本地缓存分到的权重，第二次起加载快一倍（2 台时从 32 秒降到 17 秒），不影响推理速度 | 反复用同样台数跑时可以加。注意：缓存放在 `~/.cache/llama.cpp/rpc`，**台数一变就会新增一份**（2 台时每台约 0.8 GB），磁盘紧张的 Pi（比如 cassian）不要加；用完 `rm -rf ~/.cache/llama.cpp/rpc` |

## 第 2 步：在主控上运行 —— 【在主控 Pi 上】

先 ssh 到主控：`ssh rex@<主控IP>`，然后：

```bash
cd ~/llama.cpp/build/bin
M=~/exp/models/Llama-3.2-3B-Instruct-Q4_0.gguf
RPC=10.0.0.7:50052,10.0.0.2:50052,10.0.0.3:50052,10.0.0.4:50052   # 所有 rpc-server，主控自己写在第一个
```

上面的 IP 只是示例，换成现场的。8 台就写 8 个。

### 对话（llama-cli）

```bash
./llama-cli -m $M --rpc $RPC -dev RPC0,RPC1,RPC2,RPC3 -sm tensor -c 2048            # TP，交互对话
./llama-cli -m $M --rpc $RPC -dev RPC0,RPC1,RPC2,RPC3 -sm layer  -c 2048            # PP
./llama-cli -m $M --rpc $RPC -dev RPC0,RPC1,RPC2,RPC3 -sm tensor -st -p "你好"      # 只问一句
```

### 测速（llama-bench）

```bash
./llama-bench -m $M --rpc $RPC -dev RPC0/RPC1/RPC2/RPC3 -sm tensor -p 32 -n 30 -r 2   # TP
./llama-bench -m $M --rpc $RPC -dev RPC0/RPC1/RPC2/RPC3 -sm layer  -p 32 -n 30 -r 2   # PP
./llama-bench -m $M -t 4 -p 32 -n 30 -r 2                                             # 单机（不用 rpc）
```

结果表里：
- `pp32` 行是 prefill 速度，决定首 token 时间；
- `tg30` 行是 decode 速度，也就是逐字输出的速度。

> ⚠️ **`-dev` 的分隔符不一样**：llama-cli 和 llama-server 用逗号 `RPC0,RPC1`，llama-bench 用斜杠 `RPC0/RPC1`。用错会报 `invalid device`。

### 当服务器用（llama-server，可以从浏览器访问，也可以同时处理多个请求）

```bash
./llama-server -m $M --rpc $RPC -dev RPC0,RPC1,RPC2,RPC3 -sm layer --host 0.0.0.0 --port 8080 -np 4
```

在笔记本的浏览器打开 `http://<主控IP>:8080`。`-np 4` 表示同时处理 4 个请求。

## 可以调的参数（在主控的 llama-bench / llama-cli 上）

| 参数 | 作用 | 我们的经验 / 可以探索的 |
|---|---|---|
| `-sm tensor` / `-sm layer` | TP / PP | TP 单个请求更快；PP 不会比单机快，适合装大模型 |
| `-dev RPC0/RPC1/...` | 用哪几台、按什么顺序 | 写几个就用几台。TP 台数要是 **2、4、8**，否则改进版不生效 |
| `-ts 1/1/1/0.8` | 每台分多少（不均匀切分） | 有慢 Pi 时给它少分。PP 下肯定有效，TP 下是否生效待验证 |
| `-p 512` | prompt 长度 | 看长 prompt 下的首 token 时间 |
| `-n 128` | 生成长度 | 看长输出时 decode 是否稳定 |
| `-fa on` | flash attention | 可以试试对 decode 有没有影响 |
| `-ctk q8_0 -ctv q8_0` | KV cache 量化 | 省内存，长上下文时可能更快 |
| `-ub 128` / `-b 512` | prefill 的批大小 | 影响 prefill 速度和每次同步的数据量 |
| `-r 5` | 重复次数 | 默认 5 次，嫌慢就用 2 |
| 环境变量 `GGML_RPC_NO_COMM=1` | 关掉 Pi 之间直接交换，全部经过主控中转 | 用来对比改进前后的效果 |
| 环境变量 `GGML_RPC_COMM_ALGO=rd` / `ag` | 同步算法（只在主控上设，所有 Pi 自动跟着用）。`rd`：每轮和一台交换，共 log2(台数) 轮；`ag`：一次发给所有 Pi，1 轮，但发的数据是 (台数-1) 倍 | 默认：2 台用 ag（和 rd 等价），4 台以上用 rd。Mac 模拟里 ag 在 4/8 台时串行延迟次数少 2–4 倍，真实千兆网上哪个快待验证 |
| rpc-server 的 `-t` | 每台的计算线程数 | 见上一节。主控那台可以单独少开一个线程 |

**快速模型**：`M=~/exp/models/Llama-3.2-3B-Instruct-Q4_0-embQ40.gguf`。输出层改成 Q4_0，2 台 decode 快 9%，困惑度差 0.6%。rex 上已经有了，别的主控用 `scripts/make_fast_model.sh` 生成。

还可以换模型：把其他 GGUF 文件放到主控上，`-m` 指向它。注意模型的 KV head 数要能被 TP 台数整除，否则改进版不生效。

## 怎么确认改进版真的生效了

TP 加载完以后，看任意一台 rpc-server 的输出，方法 B 启动的看 `/tmp/rpc.log`。出现下面这样的一行就是生效了：

```
[comm_init] device 0 joined comm as rank 2/4
```

意思是"4 台中的第 2 号已经加入 Pi 之间直接交换"。没有这一行，说明退回了经过主控中转的慢路径。常见原因：台数不是 2 的幂、用的是原版、模型的 KV head 数分不开、51052 端口不通。

## 注意事项

1. **所有 Pi 必须用同一个版本**（都用 `build` 或都用 `build-stock`），版本不一样会连不上或出错。
2. 换参数时 **rpc-server 不用重启**，主控那边重新运行命令就行。但如果上一次运行崩溃或者 Ctrl+C 中断了，最好把所有 rpc-server 重启一遍。
3. 每次运行，主控都会把权重重新发给所有 Pi，8 台约 15–20 秒，用 `-c` 后第二次起快一倍。这段时间不计入测出来的速度。
4. 测速时 Pi 上不要跑别的程序（比如 dllama），也不要用 Wi-Fi。
5. 用完关掉 rpc-server：【在笔记本上】
   ```bash
   for h in $(source scripts/hosts.env; echo $HEAD $WORKERS); do ssh $h pkill -x ggml-rpc-server; done
   ```
6. 想知道每一步的耗时（计算、同步、等待各多少）：启动 rpc-server 时加 `GGML_RPC_TRACE=$HOME/trace.csv`，详见 [`计时日志.md`](计时日志.md)。
7. 想把手动测的结果也汇总起来，可以用 `scripts/run_bench.sh`：它就是"启动 rpc-server + 运行 llama-bench + 记日志"，可以通过 `EXTRA="..."` 传任意 llama-bench 参数，例如 `NN=8 RPC_T=3 EXTRA="-fa on -p 512" scripts/run_bench.sh tp 1`，结果会进 `summarize.py` 的表。
