# 网络配置：交换机 + Pi 的 IP

2026-10-14 在实验室配好。**2026-10-21 交换机被恢复过出厂设置**，DHCP 和按 MAC 绑定都没了；但 8 台设备本机都设了固定 IP（`scripts/net/pi_static_ip.sh`），所以不受影响，交换机当普通交换机用即可。

## 一句话

**所有设备都插到 Netgear M4300 交换机上，用 10.77.0.0/24 网段。** 交换机会按 MAC 地址给已登记的 Pi 分配固定 IP，新 Pi 插上会自动拿到一个地址，不用做任何配置。

| 设备 | 用户名@IP | 型号 | 备注 |
|---|---|---|---|
| 交换机 M4300-28G | admin@10.77.0.1 | | telnet 或浏览器 `http://10.77.0.1` 管理，密码问组员 |
| finn | finn@10.77.0.2 | Pi 400 | |
| han | pi@10.77.0.3 | Pi 400 | |
| rex | rex@10.77.0.4 | Pi 400 | **主控**：有原模型和快速模型 |
| luthen | pi@10.77.0.5 | **Pi 4B** | 和其他几台型号不同，温度偏高（空闲 53°C） |
| cat | cat@10.77.0.6 | 非 Pi（ubuntu） | 还没登记 MAC |
| cassian | cassian@10.77.0.7 | Pi 400 | 本机固定 IP |
| jarjar | jarjar@10.77.0.8 | Pi 4B | 本机固定 IP（10-21 加入；注意电源要用 5.1V/3A） |
| crosshair | crosshair@10.77.0.9 | Pi 4B | 本机固定 IP（10-21 加入） |
| 其他新设备 | 自动分配 10.77.0.101–199 | | 在交换机上 `show ip dhcp binding` 能查到 |
| 笔记本 | 手动设 10.77.0.100（或用 DHCP 自动拿） | | |

为什么不用 10.0.0.x：很多人的笔记本连的 Wi-Fi 也是 10.0.x.x，会冲突，笔记本就连不到 Pi。白板上的 .2/.3/.4/.5 编号沿用了下来。

## 笔记本怎么接入 —— 【在笔记本上】

用网线插到交换机任意端口。交换机开着 DHCP，笔记本一般会自动拿到 10.77.0.1xx 的地址。

想固定成 10.77.0.100（macOS）：

```bash
networksetup -listallnetworkservices                 # 找到有线网卡的名字，比如 "Linksys USB3GIGV1"
networksetup -setmanual "有线网卡名字" 10.77.0.100 255.255.255.0
# 改回自动：networksetup -setdhcp "有线网卡名字"
```

不设网关，这样笔记本访问外网仍然走 Wi-Fi。

## Pi 这边

- **已登记的 4 台（finn/han/rex/luthen）**：既改成了固定 IP（NetworkManager 里 `ipv4.method manual`），交换机上也按 MAC 绑定了同样的地址。两者一致，所以就算交换机的 DHCP 坏了也不影响。原来的 10.0.0.x 地址也保留着。
- **新 Pi**：保持系统默认（DHCP）直接插上就行。想让它每次都是同一个地址，按下一节在交换机上登记 MAC。

> **之前网络时断时续的原因**：Pi 默认用 DHCP 获取地址，而交换机原来没开 DHCP。NetworkManager 每等 45 秒拿不到地址就判定失败，把网口整个重置一次，ssh 和实验都会断。现在交换机有 DHCP 了，这个问题不会再出现。如果哪天换了交换机，用 `scripts/net/pi_static_ip.sh` 把 Pi 改成固定 IP。

查一台 Pi 的 MAC：【在那台 Pi 上】`cat /sys/class/net/eth0/address`

## 在交换机上登记一台新 Pi —— 【在笔记本上】

```bash
telnet 10.77.0.1          # 用户名 admin
```

```
enable
configure
ip dhcp pool grogu                        # 名字随便起，一台一个
hardware-address d8:3a:dd:xx:xx:xx        # 先写 MAC
host 10.77.0.8 255.255.255.0              # 再写 IP（顺序不能反）
client-name grogu
exit
exit
write memory                              # 保存，问 y/n 时输 y
```

然后让那台 Pi 重新拿地址：拔插网线，或者【在那台 Pi 上】`sudo nmcli con up "$(nmcli -t -f NAME,TYPE con show | awk -F: '$2=="802-3-ethernet"{print $1; exit}')"`。

## 交换机上做过的配置（备查）

```
service dhcp
ip dhcp excluded-address 10.77.0.1 10.77.0.100      # .1–.100 留给手动和按 MAC 绑定
ip dhcp excluded-address 10.77.0.200 10.77.0.254
ip dhcp pool dat300                                  # 动态分配：.101–.199
  network 10.77.0.0 255.255.255.0
  lease 7
ip dhcp pool finn / han / rex / luthen / cassian     # 按 MAC 绑定，见上表
interface vlan 1
  ip address 10.77.0.1 255.255.255.0                 # 交换机自己的管理地址（原来是 DHCP，拿不到就变成 169.254.100.100）
write memory
```

查看：`show ip dhcp pool configuration all`、`show ip dhcp binding`、`show running-config`。

如果交换机被恢复出厂设置，它的地址会变回 169.254.100.100。这时从一台 Pi 上临时加个同网段地址就能连上：`sudo ip addr add 169.254.10.4/16 dev eth0`，然后 `telnet 169.254.100.100`。

## 网络质量（实测）

- Pi 之间 ping：0% 丢包，往返 0.05–0.15 ms，比原来经过小米路由器时低很多。
- 所有 Pi 都是 1000Mb 全双工。
- Pi 不能上网，时钟会乱。跑实验前【在笔记本上】同步一下时钟（计时日志跨机器对比时有用）：
  ```bash
  for h in $(source scripts/hosts.env; echo $HEAD $WORKERS); do ssh -t $h "sudo date -s @$(date +%s)"; done
  ```
